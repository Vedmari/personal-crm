# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/keep-in-touch/spec.md` и `specs/notes/spec.md`.

Что есть сейчас:

- `contacts` и `notes` в PostgreSQL через Drizzle. Необязательные текстовые поля хранятся пустой строкой. Удаление помечает строку `deleted_at` и стирает её, когда закрывается сообщение с «Вернуть».
- `contacts.updated_at` служит меткой версии для формы «Изменить»: сохранение проходит, только если контакт не меняли с момента открытия формы.
- Время заметки ставит база (`now()`). Индекс `notes (contact_id, created_at)` уже есть.
- Сообщение с «Вернуть» после удаления — `toastWithUndo` в `src/components/confirm-delete.tsx` (`sonner`, 10 секунд). Подпись кнопки в нём зашита: «Вернуть».
- Главная страница: шапка, закреплённая строка поиска высотой 64px, ниже счётчик и алфавитный список. `revealContact` после добавления ищет строку списка по id `contact-<id>`.
- Карточка: список полей (`DetailRow`), стикер «О чём договорились», лист заметок.
- На сервере образ `node:24-slim` без настройки часового пояса, то есть процесс приложения работает в UTC. `formatNoteDate` форматирует время без явного часового пояса, поэтому на сервере время заметок, скорее всего, на 3 часа меньше московского.
- В зависимостях уже есть `@base-ui/react` 1.8.0 с компонентом `select`.

## Goals / Non-Goals

**Goals:**

- Карточка и блок считают срок одной и той же формулой и не расходятся.
- Все дни и время — по московскому времени, независимо от часового пояса сервера и устройства.
- Смена частоты не задевает механизм версий формы «Изменить».
- «Связались» не вводит второго источника «последнего общения»: это обычная заметка.

**Non-Goals:**

- Пересчёт без перезагрузки: если страница открыта, блок обновится при следующем открытии или после действия, которое обновляет страницу.
- Перенос заметок или других записей в базе: меняется только показ времени.

## Decisions

### 1. Два новых необязательных поля в `contacts`

- `keep_in_touch_every`: перечисление `keep_in_touch_interval` (`week`, `month`, `quarter`, `year`). `NULL` означает «Не задано».
- `keep_in_touch_since timestamptz`: момент, когда выбрали текущую частоту. Нужен для правила «без заметок срок отсчитывается от выбора частоты». При «Не задано» хранит `NULL`.

Почему перечисление, а не пустая строка, как у других полей: это не свободный текст. Перечисление не пропустит в базу неизвестное значение, а `NULL` прямо означает «не задано».

Другие варианты:

- Отдельная таблица настроек: лишняя связь для одного значения на контакт.
- Отсчёт от `updated_at` или `created_at` вместо отдельного поля. `updated_at` меняется при любой правке контакта. Вариант с `created_at` пользователь отклонил.

Значения у существующих контактов не заполняются, у всех остаётся `NULL`, поведение не меняется.

### 2. Смена частоты не трогает `updated_at`

Если менять `updated_at`, форма «Изменить», открытая в другой вкладке, откажется сохраняться, хотя ни одно её поле не менялось. Частота меняется отдельным запросом, который пишет только два новых поля. Форма «Изменить» эти поля не отправляет и поэтому не может их затереть.

При одновременной смене частоты в двух вкладках сохранится последний выбор. Это допустимо: значение выбирается одним нажатием, набранный текст не теряется.

### 3. Срок считается в SQL одним выражением

Общий SQL-фрагмент Drizzle используется и в запросе блока, и в запросе карточки:

```sql
last_contact = coalesce(
  (select max(created_at) from notes
    where contact_id = c.id and deleted_at is null),
  c.keep_in_touch_since)
due_day      = ((last_contact at time zone 'Europe/Moscow')::date + <период>)::date
today        = (now() at time zone 'Europe/Moscow')::date
overdue_days = today - due_day   -- больше 0: просрочен
```

Период: `week` → `interval '7 days'`, `month` → `'1 month'`, `quarter` → `'3 months'`, `year` → `'1 year'`. Сложение дат с месяцами в PostgreSQL само обрабатывает конец месяца: 31 января + 1 месяц = 28 февраля.

Даты дня (`due_day`, день последней заметки) возвращаются как `date`, без часового пояса. В JS они форматируются как календарный день, поэтому сервер в UTC не сдвинет день.

Блок: контакты с `keep_in_touch_every is not null`, `deleted_at is null`, `overdue_days > 0`. Порядок: `overdue_days desc`, затем имя с `collate "ru-x-icu"` и `id`, как в списке. Подзапрос `max(created_at)` использует существующий индекс `notes (contact_id, created_at)`.

Другой вариант — считать в JS. Тогда пришлось бы загружать все контакты с частотой вместе с последними заметками и отдельно разбирать конец месяца и часовой пояс. SQL даёт одну формулу для карточки и блока.

### 4. Выбор частоты в карточке — `Select` на Base UI

Новая строка «Как часто общаться» в списке полей карточки, после «Откуда знакомы». Под значением строка срока. Компонент `src/components/ui/select.tsx` (обёртка shadcn над `@base-ui/react/select`, новых пакетов нет) оформлен токенами. Клиентский компонент выбора частоты:

- сразу показывает выбранное значение;
- вызывает серверное действие `setKeepInTouchAction(contactId, interval | null)`;
- при ошибке возвращает прежнее значение и показывает сообщение через `sonner`, как другие действия;
- при успехе вызывает `refresh()`, чтобы пересчитать строку срока.

Действие проверяет значение по списку допустимых (`validation.ts`) и обновляет строку `where id = … and deleted_at is null`. `keep_in_touch_since` становится `now()`, только если частота изменилась. Повторный выбор того же значения отсчёт не сбрасывает. Удалённый контакт → «Контакт не найден. Обновите страницу.»

Другие варианты:

- Обычный `<select>`: выпадающий список рисует система, оформить его под лист ежедневника нельзя.
- Пять кнопок-переключателей: на телефоне пять подписей не помещаются в строку.

### 5. Блок на главной — серверный компонент и клиентский список

`page.tsx` выводит блок внутри `main` перед `ContactList`, в своём `Suspense`. Блок стоит под строкой поиска, а не над ней: он исчезает, когда начинается поиск. Если бы блок стоял выше, строка поиска прыгала бы вверх при первой набранной букве.

Серверная часть читает `q`. Если поиск не пустой или просроченных нет, она ничего не выводит. Иначе получает всех просроченных и передаёт их клиентскому компоненту. Он показывает первые пять и переключает «Показать все N» / «Свернуть» без запроса к серверу. Просроченных в личной CRM десятки, а не тысячи. Состояние «раскрыто» живёт в компоненте и переживает обновление данных после «Связались», но не перезагрузку страницы.

Другой вариант — параметр `?all=1` в адресе. Он переживает перезагрузку, но засоряет адрес и ссылки поиска.

Строка блока похожа на строку списка: кружок, имя, подпись — и кнопка «Связались» справа. У строки нет id `contact-<id>`: по нему `revealContact` ищет строку алфавитного списка и иначе прокрутил бы к блоку.

### 6. «Связались» — обычная заметка с текстом «Связались»

Серверное действие `markContactedAction(contactId)` проверяет, что контакт не удалён, и добавляет заметку существующим `addNote(id, "Связались")`. Возвращает номер заметки и имя контакта, вызывает `refresh()`. Срок пересчитывается сам по правилу «последняя заметка», отдельного поля нет.

Почему заметка, а не отметка в `contacts`: так решил пользователь. Остаётся один источник последнего общения, история видна в ленте, ошибочную отметку можно удалить корзиной, как любую заметку.

Кнопка — соседний элемент ссылки на карточку, а не вложенный: кнопка внутри ссылки — неправильная разметка, и нажатие открывало бы карточку. На телефоне кнопка показана только значком (галочка), как «Добавить» и «Изменить». Подпись для экранного диктора: «Связались: Анна Смирнова».

После нажатия строка сразу прячется (`useOptimistic`), не дожидаясь ответа сервера. Повторное нажатие невозможно, лишних заметок не будет. При ошибке строка возвращается и показывается сообщение. Фокус переходит на кнопку «Связались» следующей строки, у последней строки — предыдущей, а если строк не осталось — на строку поиска.

### 7. «Отменить» удаляет заметку сразу и насовсем

`toastWithUndo` получает необязательную подпись кнопки (по умолчанию «Вернуть»). Для «Связались» — сообщение «Анна Смирнова: отметили, что связались» с «Отменить», 10 секунд, как при удалении. Когда сообщение закрывается само, ничего не происходит: заметка остаётся.

«Отменить» вызывает `undoMarkContactedAction(noteId)`. Оно стирает строку `where id = … and body = 'Связались' and deleted_at is null`. Условие по тексту не даст случайным номером стереть обычную заметку. После успеха — короткое сообщение «Отметка снята», контакт возвращается в блок после `refresh()`.

Другой вариант — пометить заметку `deleted_at` и стереть позже, как при удалении. Здесь это лишнее: у отмены нет своего «Вернуть», а заметке 10 секунд от роду.

### 8. Все даты и время — по Москве

Константа `MOSCOW_TIME_ZONE = "Europe/Moscow"` в `src/lib/format.ts`. Она задаёт `timeZone` во всех форматтерах `Intl.DateTimeFormat`, а SQL-фрагмент срока использует то же значение. Так время заметок (`formatNoteDate`) и дни срока одинаковы на этом компьютере, на сервере в UTC и в браузере из любого часового пояса: страницы собираются на сервере, а форматтер с явным `timeZone` не зависит от машины.

Другой вариант — `TZ=Europe/Moscow` в образе и `docker compose`. Это работает только там, где переменную не забыли: локально на Windows и в любом новом окружении снова будет своё время. Явный `timeZone` в коде надёжнее.

Москва без перехода на летнее время, поэтому смещение всегда +3 часа.

### 9. Тексты и даты

В `src/lib/format.ts` добавляется форматирование дня: «24 ноября», а год пишется, только если он не текущий по Москве («1 декабря 2025»). Подписи частот: «Раз в неделю», «Раз в месяц», «Раз в квартал», «Раз в год». В подписи строки блока они пишутся со строчной буквы. Тексты карточки, блока и сообщений — из спеки.

### 10. Тестовые данные

`scripts/seed.mts` задаёт частоту примерно каждому десятому контакту, `keep_in_touch_since` — дата создания контакта. У seed-контактов уже есть заметки за последние годы, так что часть сразу просрочена и блок виден на свежей базе. Правило seed не меняется: скрипт работает только на пустой базе.

## Risks / Trade-offs

- [Блок не обновляется в полночь, пока страница открыта] → Срок пересчитывается при каждом открытии и обновлении страницы. Для личной CRM этого достаточно.
- [Случайное нажатие «Связались»] → 10 секунд есть «Отменить». Позже заметку «Связались» можно удалить корзиной в карточке.
- [Вкладку закрыли, пока висело «Отменить»] → Заметка остаётся. Так и задумано: нажатие и есть отметка.
- [Время старых заметок на сервере изменится на +3 часа] → Это исправление показа, записи в базе не меняются. Тестовые данные на сервере просто покажутся по Москве.
- [Подзапрос на каждый контакт с частотой] → Его покрывает индекс `notes (contact_id, created_at)`. На 1000 тестовых контактов нагрузка заметной не будет.
- [Перечисление в PostgreSQL сложнее расширить, например добавить «раз в две недели»] → Добавить значение можно миграцией `ALTER TYPE … ADD VALUE`. Удалить значение сложнее, но такой задачи нет.

## Migration Plan

1. `pnpm db:generate` создаёт миграцию `0003`: новый тип `keep_in_touch_interval` и два необязательных столбца без заполнения.
2. Локально — `pnpm db:migrate`. На сервере миграцию, как обычно, применяет разовый контейнер до старта нового образа.
3. Откат: предыдущий образ не читает новые столбцы и работает с ними без ошибок. Поэтому ручной откат `deploy/rollback.sh` безопасен без отката миграции. После отката время заметок на сервере снова покажется по UTC, а заметки «Связались» останутся обычными заметками.
