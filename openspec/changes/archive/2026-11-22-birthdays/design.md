# Design

## Context

Главная загружает «Пора связаться» и алфавитный список раздельно. Список выдаёт по 100 контактов. Даты в CRM считаются по Москве. Формы создания и редактирования используют общий разбор полей, а сохранение открытой карточки проверяет её версию по `updatedAt`.

## Goals / Non-Goals

Цель — получить все дни рождения за семь дней одним серверным запросом и использовать существующий цикл сохранения контакта. Доставка уведомлений и вычисление возраста за рамками предложения.

## Decisions

1. Добавить в `contacts` три допускающих NULL целочисленных столбца: `birth_day`, `birth_month` и `birth_year`. Хранить пустую дату тремя NULL. Для записанного дня рождения обязательны день и месяц, неизвестный год остаётся NULL. В форме предусмотреть ввод дня, месяца и отдельного необязательного года. На сервере и ограничением CHECK в базе проверить совместное заполнение частей и существование даты. Без года допускать 29 февраля, с годом проверять високосность указанного года. Сохранять части одной операцией. У старой формы все ключи даты отсутствуют — сохранить прежнюю дату. Новая форма передаёт все три поля, включая явно очищенные значения.
2. Из семи московских календарных дат, начиная с сегодняшней, выбрать совпадения по месяцу и дню рождения. На 28 февраля невисокосного года в выборку также попадает 29 февраля. Такой обход дат охватывает январь при переходе года и исключает попытку создать несуществующую дату. Передавать опорный день в тестах явно. При известном годе учитывать только даты поздравления начиная с даты рождения. При пустом годе сравнивать только месяц и день.
3. Выбирать из всей таблицы контактов с условиями владельца из серверной сессии, активной записи и заполненной даты. В блок передавать только ID, имя и день поздравления. Сортировать по дню, затем по принятому в книге порядку имени (`ru-x-icu`) и ID. Фильтрация уже загруженной страницы пропустила бы часть людей.
4. Разместить серверный блок после «Пора связаться» перед алфавитным списком. Использовать те же условия обычного списка при поиске и выборе группы. Имя сделать ссылкой в карточку, рядом вывести день и месяц. После изменения даты использовать штатное обновление главной и карточки.

## Risks / Trade-offs

- Смена года и расхождение между временем сервера и Москвы могут сдвинуть границы. Проверить выборку с фиксированным временем у московской полуночи.
- Дата рождения относится к персональным данным. Проверить выборку с двумя владельцами, а чтение и запись карточки проводить через действующие проверки доступа.
- Одновременное редактирование может затереть новую дату. Сохранить проверку версии всего контакта в действии «Изменить».

## Migration Plan

Добавить три столбца и проверку допустимых значений одной миграцией Drizzle до запуска новой версии приложения. Существующие строки получают NULL без заполнения дат. При откате приложения столбцы остаются в базе, поэтому уже введённые даты сохраняются.
